# Kanon v1.0.0 Debloat Baseline

This report fixes the comparison baseline for the v1.1.0 deletion-led
refactor. The source is the immutable `v1.0.0` tag at commit
`21c6d1df2cd2676354a9de6bab96e4651781a608`.

Measurements were reproduced on 2026-08-11 with Git 2.44.0, Node.js 25.8.1,
and npm 11.18.0. Sizes are decimal bytes and line counts are physical lines,
including blank lines.

| Measure | v1.0.0 baseline | Definition |
| --- | ---: | --- |
| Published package files | 129 | npm dry-run pack `entryCount` from a clean tag archive |
| Published unpacked size | 708,725 bytes | npm dry-run pack `unpackedSize` from the same artifact |
| Shipped runtime JavaScript files | 81 | Tracked `.js` files below `runtime/` |
| Shipped runtime JavaScript lines | 23,620 | Physical lines in those 81 files |
| Tracked repository files | 664 | Recursive Git tree entries |
| Tracked repository lines | 175,641 | Physical lines in non-binary tracked blobs |
| Tracked repository bytes | 117,873,237 bytes | Sum of Git blob sizes |
| CI workflow lines | 597 | Physical lines in tracked workflow YAML files |

## Reproduce repository measurements

Run these POSIX-shell commands from any checkout containing the tag. The
regular expression `^` makes Git emit every physical line; `-I` excludes
binary blobs rather than interpreting their bytes as text.

```sh
BASELINE_REF=v1.0.0

git rev-list -n 1 "$BASELINE_REF"

# Tracked repository files: 664
git ls-tree -r --name-only "$BASELINE_REF" | wc -l

# Tracked repository bytes: 117873237
git ls-tree -r -l "$BASELINE_REF" |
  awk '$2 == "blob" { total += $4 } END { printf "%.0f\n", total }'

# Tracked non-binary physical lines: 175641
git grep -I -n -e '^' "$BASELINE_REF" | wc -l

# Shipped runtime JavaScript files: 81
git ls-tree -r --name-only "$BASELINE_REF" -- runtime |
  awk '/\.js$/ { count += 1 } END { print count + 0 }'

# Shipped runtime JavaScript physical lines: 23620
git grep -I -n -e '^' "$BASELINE_REF" -- \
  'runtime/*.js' 'runtime/**/*.js' | wc -l

# CI workflow physical lines: 597
git grep -I -n -e '^' "$BASELINE_REF" -- \
  '.github/workflows/*.yml' '.github/workflows/*.yaml' | wc -l
```

The runtime measure deliberately uses `runtime/**/*.js`, not the repository's
two source wrappers below `bin/`; the published package stages executable
JavaScript below `runtime/`.

## Reproduce package measurements

Build from a clean Git archive so untracked or later working-tree files cannot
affect the result. The staging directory is created below Node's canonical
temporary directory because the package builder rejects output elsewhere.
The public package manifest has no lifecycle scripts, and no dependency install
is needed for this build.

```sh
BASELINE_DIR="$(
  node --input-type=module -e '
    import fs from "node:fs";
    import os from "node:os";
    import path from "node:path";
    process.stdout.write(
      fs.mkdtempSync(path.join(os.tmpdir(), "kanon-v1.0.0-"))
    );
  '
)"

git archive --format=tar \
  --output="$BASELINE_DIR/source.tar" \
  v1.0.0
tar -xf "$BASELINE_DIR/source.tar" -C "$BASELINE_DIR"

node "$BASELINE_DIR/scripts/build-package.js" \
  --output "$BASELINE_DIR/package"

npm pack --dry-run --json "$BASELINE_DIR/package" |
  node -e '
    let input = "";
    process.stdin.setEncoding("utf8");
    process.stdin.on("data", (chunk) => { input += chunk; });
    process.stdin.on("end", () => {
      const result = JSON.parse(input)[0];
      process.stdout.write(JSON.stringify({
        entryCount: result.entryCount,
        unpackedSize: result.unpackedSize
      }) + "\n");
    });
  '
```

Expected final output:

```json
{"entryCount":129,"unpackedSize":708725}
```

The temporary `BASELINE_DIR` can be removed after inspecting the result.
