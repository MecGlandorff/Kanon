# Kanon v1.0.0 Public JavaScript Contract

This Phase 0 inventory freezes the JavaScript package boundary that v1.1.0
must preserve. It describes the immutable `v1.0.0` tag at commit
`21c6d1df2cd2676354a9de6bab96e4651781a608`; the relevant manifest, package
builder, artifact allowlist, and source facade are unchanged at the start of
the refactor branch.

## Published package boundary

The npm artifact is a plugin distribution container, not a JavaScript library.
Its generated root manifest has no `main`, `module`, `exports`, `browser`,
`types`, or `typings` field, and the artifact contains neither a root
`index.js` nor the repository's `src/index.js`. It also has no npm `bin` field;
the public executable boundary is the skill-wrapper contract inventoried in
`docs/v1.1.0-public-cli-contract.md`.

The shipped files below `runtime/` are ESM implementation modules selected by
an exact build allowlist. `runtime/package.json` establishes their private ESM
boundary and one internal import-map binding. Those files can be addressed by
path after installation because the package has no export map, but no such
deep import is documented or advertised as a supported API. Their module
exports are therefore implementation reachability, not a v1 public
compatibility surface.

Adding a library entry point would expand the public product and is outside
this deletion-led release. Removing or reorganizing an implementation module
is not by itself a public export break, provided the documented wrappers,
outputs, state, and artifact contract remain compatible.

## Repository-only facade

The development manifest is explicitly `private`. Its `src/index.js` facade is
not copied to the published artifact and is used only by repository tests and
development code. At v1.0.0 it re-exports 35 names, grouped here so later
reachability work does not mistake them for published entry points:

- analysis and questions: `analyzeRepo`, `answerRepoQuestion`,
  `classifyQuestionIntent`, `extractLiteralSearch`;
- configuration: `DEFAULT_CONFIG`, `inspectKanonConfig`, `readKanonConfig`,
  `scanOptionsFromConfig`, `validateConfig`;
- CLI and evidence: `createRunId`, `runCli`;
- persistence: `addKanonTodo`, `completeKanonTodo`, `inspectKanonTodos`,
  `inspectPreviousHandoff`, `inspectPreviousState`, `parseKanonTodoMarkdown`,
  `readKanonTodos`, `readPreviousState`, `validatePersistedState`,
  `writeKanonOutputs`;
- continuity and rendering: `buildContinuityArtifactMetadata`,
  `buildContinuityReport`, `renderAsk`, `renderBrief`, `renderResume`,
  `renderTodoList`, `renderVerify`;
- verification, Git, paths, and versions: `verifyReadme`, `inspectGit`,
  `resolveContainedPath`, `sanitizeFilenameComponent`,
  `CONFIG_SCHEMA_VERSION`, `STATE_SCHEMA_VERSION`, `VERSION`.

This facade may be narrowed with the legacy compatibility closure when its
repository consumers are migrated. Doing so does not require a public
compatibility escalation solely because a name was re-exported here.

## Evidence and reproduction

The boundary is defined by `package.json`, `src/index.js`,
`scripts/build-package.js`, `scripts/lib/artifact-files.js`, `README.md`, and
`packaging/README.md`. The package allowlist and generated-manifest assertions
are covered by `test/v1-plugin.test.js` and artifact conformance.

After inspecting the invoked definitions, reproduce the static baseline and
focused package check with:

```sh
git diff --exit-code v1.0.0 -- \
  package.json src/index.js scripts/build-package.js \
  scripts/lib/artifact-files.js README.md packaging/README.md

node --test test/v1-plugin.test.js
```
