# Kanon v1.0.0 Compatibility-Write Success Contract

This Phase 0 characterization freezes the successful public results and
repository mutations of the legacy `refresh` and `todo` workflows that v1.1.0
must preserve while deleting their legacy runtime closure. It describes the
immutable `v1.0.0` tag at commit
`21c6d1df2cd2676354a9de6bab96e4651781a608`; the named canonical sources and
generated runtime copies were byte-identical at the start of this inventory.

This boundary is deliberately limited to successful calls. Argument routing
and process exit meanings are recorded in
`docs/v1.1.0-public-cli-contract.md`; checkpoint compatibility is recorded in
`docs/v1.1.0-legacy-state-contract.md`. Rejected persistence, read-only media,
replacement races, and concurrent writers remain separate characterization
work before the legacy closure can be replaced.

## Shared write boundary

Both commands resolve `--root` to an absolute repository root and write only
below `.kanon/`. They use contained persistence primitives, including
same-directory atomic replacement for replaced files and a bounded contained
append for the evidence ledger, and treat repository content as untrusted
data. Successful calls write their result to standard output, leave standard
error empty, and exit zero through the executable wrapper.

Neither command returns the stable `kanon-stable-skill-result-v1` envelope.
Their JSON results are untagged compatibility objects. This distinction must
remain explicit if all public commands are routed through one future dispatch
layer.

## `refresh`

`refresh` performs a fresh legacy repository analysis, renders continuity, and
prints text even when the globally accepted `--json` flag is present. A normal
first refresh writes and reports paths in this order:

```text
Kanon refreshed <absolute-root>/.kanon
- .kanon/.gitignore
- .kanon/KANON.md
- .kanon/STATE.json
- .kanon/EVIDENCE.jsonl
- .kanon/HANDOFF.md
- .kanon/config.json
- .kanon/snapshots/<run-id>.json
```

Each bounded warning is appended as `Warning: <sanitized text>`. Reaching the
snapshot retention limit omits the snapshot path and adds a warning. The
reported evidence path remains in the fixed manifest when retention bounds
prevent additional evidence records.

The managed outputs have these roles:

| Path | Successful behavior |
| --- | --- |
| `.kanon/.gitignore` | Created or extended to ignore generated state while allowing `.gitignore`, `KANON.md`, and `TODO.md`. Existing unrelated lines are retained. |
| `.kanon/KANON.md` | Replaced with the bounded orientation rendering; `--deep` selects its existing deeper rendering mode. |
| `.kanon/STATE.json` | Replaced with newline-terminated, validated schema-2 state. |
| `.kanon/EVIDENCE.jsonl` | Appended within byte and record retention limits. |
| `.kanon/HANDOFF.md` | Replaced with bounded continuity rendering using safe prior state, handoff, and TODO observations. |
| `.kanon/config.json` | Created with default schema-2 configuration only when absent; an existing valid configuration is retained. |
| `.kanon/snapshots/<run-id>.json` | Created when snapshot retention permits and contains the same state value as `STATE.json`. |

`refresh` does not create or replace `.kanon/TODO.md`. It reads recognized TODO
items only to render the handoff. Prior state and warning behavior are covered
by the legacy-state contract rather than duplicated here.

## `todo` storage

`todo` stores human-owned follow-up in `.kanon/TODO.md`; it does not run the
repository analyzer or create `.kanon/config.json`. The first successful add
creates this header and an unchecked Markdown item:

```markdown
# Kanon TODO

- [ ] first item
```

Recognized items match Markdown checkboxes with a space, `x`, or `X`. Indented
nonempty lines following an item are its details. Other Markdown is retained
on add and completion but is not returned as a TODO. Public item numbers are
the one-based order of recognized items, not durable stored identifiers.

Every returned item has exactly these fields:

| Field | Meaning |
| --- | --- |
| `number` | Current one-based recognized-item position. |
| `done` | Whether the checkbox contains `x` or `X`. |
| `text` | Trimmed, terminal-sanitized title. |
| `details` | Sanitized recognized continuation lines. |
| `line` | Current one-based source line in `TODO.md`. |
| `trust` | Literal `repository-untrusted`. |

Adding positional text joins all values after `add` with one space. Successful
stdin input preserves multiple lines as an item title plus details after
normalizing line endings, tabs, ANSI/OSC sequences, controls, and bidi display
characters through the existing trust boundary. Leading and trailing blank
lines are removed. The entire file remains subject to the configured TODO byte
bound.

## `todo` results

The successful machine-readable shapes are exact untagged objects:

```text
list: { todos: Todo[] }
add:  { path: ".kanon/TODO.md", todo: Todo }
done: { path: ".kanon/TODO.md", todo: Todo, changed: boolean }
```

JSON `list` always returns every recognized item, including completed items;
`--all` affects only text rendering. Text `list` hides completed items by
default, while `--all` shows them, without renumbering the remaining items.
An empty text list distinguishes `No open Kanon todos.` from
`No Kanon todos found.` under `--all`.

Text mutations render one line:

```text
Added Kanon todo #<number>: <sanitized title>
Completed Kanon todo #<number>: <sanitized title>
Kanon todo #<number> was already complete: <sanitized title>
```

Completing an open item atomically rewrites the file with its selected checkbox
marked and returns `changed: true`; that rewrite normalizes line endings to LF
and ensures a trailing newline. Completing it again is successful and
idempotent, returns `changed: false`, and does not rewrite the file.

## Evidence and reproduction

The boundary is defined by `src/cli/write.js`, `src/cli/todo.js`,
`src/cli/args.js`, `src/cli/io.js`, `src/persist.js`,
`src/render/continuity.js`, and their generated runtime copies. The focused
regression coverage is in `test/kanon.test.js`.

After inspecting the invoked definitions, confirm release-source identity and
run the characterization with:

```sh
git diff --exit-code v1.0.0 -- \
  bin/kanon-write.js src/cli/args.js src/cli/io.js \
  src/cli/todo.js src/cli/write.js src/persist.js \
  src/render/continuity.js runtime

node --test \
  --test-name-pattern="compatibility (refresh|todo) preserves" \
  test/kanon.test.js
```
