# Kanon v1.0.0 Public Executable Contract

This Phase 0 inventory freezes the published wrapper and command-line boundary
that v1.1.0 must preserve. It describes the immutable `v1.0.0` tag at commit
`21c6d1df2cd2676354a9de6bab96e4651781a608` and the byte-identical executable
sources at the start of the refactor branch.

This inventory is deliberately limited to executable routing, arguments,
output modes, and process exit meanings. JavaScript exports are inventoried in
`docs/v1.1.0-public-javascript-contract.md`, and the repository-local legacy
checkpoint is inventoried in `docs/v1.1.0-legacy-state-contract.md`. Result
schemas, other persistence, and status or diagnostic vocabularies remain
separate Phase 0 work.

## Published launch topology

The staged npm manifest has no `bin`, `main`, or `exports` field. Public
execution starts at the plugin skill wrappers. Each logical wrapper ships in a
Bash and a PowerShell form, for 24 wrapper files in total.

| Surface | Wrapper commands | Fixed runtime |
| --- | --- | --- |
| Stable skills | `orient`, `resume`, `verify`, `status`, `steer`, `aswitch` | `runtime/bin/kanon-v1.js` |
| Compatibility reads | `ask`, `brief`, `resume`, `verify` | `runtime/bin/kanon-v1.js` |
| Compatibility writes | `refresh`, `todo` | `runtime/bin/kanon-write.js` |

The stable wrappers live below their matching `skills/<name>/scripts/`
directories. Compatibility wrappers live below `skills/kanon/scripts/`.
Consequently, `resume` and `verify` each have both a stable-skill wrapper and a
compatibility wrapper; both copies select the same fixed command in the same v1
runtime.

All wrappers call one platform-specific shared dispatcher. The dispatcher
accepts only the ten command names shown above, chooses one of the two runtime
bins, resolves an allowed Node.js major, scrubs hostile Node environment
variables, and forwards the original argument vector unchanged.

## Stable and compatibility-read arguments

The v1 runtime accepts the six stable commands plus the `ask` and `brief`
aliases. Options may appear before or after positional arguments.

| Command | Positional input | Command-specific input | Route |
| --- | --- | --- | --- |
| `orient` | Optional task text | Optional `--task TEXT` overrides positional task text | `orient` |
| `brief` | Optional task text | Optional `--task TEXT` overrides positional task text | `orient` |
| `ask` | Required narrow question | Exactly one purpose, run, test, Git-state, documentation-drift, or literal-search family | `orient`, or `verify` for documentation drift |
| `resume` | None | Optional `--task TEXT` | `resume` |
| `verify` | Zero or one relative documentation target; default `README.md` | Optional `--task TEXT`; optional receipt JSON via `--receipt-stdin` | `verify` |
| `status` | None | Optional receipt JSON via `--receipt-stdin`; no task | `status` |
| `steer` | None | Exactly `--state-stdin` with a JSON value | `steer` |
| `aswitch` | None | Exactly `--request-stdin` with a JSON value | `aswitch` |

Every row accepts `--json` and `--root PATH`. Global informational options are
`--help`/`-h` and `--version`/`-v`. Help or version takes precedence over
command routing and does not read standard input.

The v1 argument vector is capped at 64 entries, 8,192 UTF-16 code units per
entry, and 16 KiB in total UTF-8 bytes including separators. `--root` is capped at
8 KiB and `--task` at 2 KiB. Receipt, steer-state, and aswitch-request input is
capped at 16 KiB, 32 KiB, and 64 KiB respectively; empty, malformed UTF-8,
malformed JSON, and over-limit input is rejected.

The parser also accepts `--receipt-stdin` for `orient`, `brief`, `resume`, and
`ask`, although help does not advertise those combinations. For an
orient-routed command the resulting invocation is invalid and returns an
`Unknown` result envelope rather than a CLI parse failure. Documentation-drift
`ask` routes to `verify` and therefore consumes the receipt. `ask --task` is
parsed but the question remains the task. These are observed v1.0.0 behaviors,
not newly endorsed interfaces; tightening them during refactoring requires an
explicit compatibility decision.

## Compatibility-write arguments

The write runtime accepts only `refresh` and `todo`.

```text
kanon refresh [--deep] [--root PATH]
kanon todo list [--all] [--json] [--root PATH]
kanon todo add "describe the work" [--json] [--root PATH]
kanon todo add --stdin [--json] [--root PATH]
kanon todo done <number> [--json] [--root PATH]
```

`todo` with no action defaults to `list`. `todo add --stdin` requires piped
input and applies the configured TODO byte bound, which defaults to 256 KiB.
The write parser also recognizes `--help`/`-h`, `--version`/`-v`, `--deep`,
`--json`, `--stdin`, `--all`, and `--root` globally.

The v1.0.0 write parser is permissive beyond the documented forms: `refresh`
ignores `--json`, `--stdin`, `--all`, and positional arguments; `todo` ignores
`--deep`; `todo list` and `todo done` ignore surplus positional arguments after
the values they consume. These are observed compatibility behaviors. A narrow
replacement should characterize callers before rejecting combinations that
v1.0.0 accepted. Unlike the v1 parser, this legacy parser applies no separate
aggregate argument-vector cap; downstream TODO and persistence bounds still
apply.

## Output modes and exit meanings

| Condition | Standard output | Standard error | Exit code |
| --- | --- | --- | ---: |
| Help, version, or successful command | Requested text or JSON | Empty in the ordinary case | 0 |
| Stable semantic result is `Stale` or `Unknown` | Normal text or `kanon-stable-skill-result-v1` JSON | Empty in the ordinary case | 0 |
| Thrown runtime argument, input, or write failure | Empty or any output written before failure | Error message | 1 |
| Explicit fail-closed launcher rejection, including an unsupported fixed dispatch command or rejected Node.js resolution | Empty in the ordinary case | Launcher diagnostic | 127 |

Stable `--json` always serializes the common stable result envelope. Stable
text output includes the status and a fenced, explicitly untrusted JSON report.
`refresh` has text output only even if the globally parsed `--json` flag is
present. `todo --json` emits the list or mutation result as JSON; its default
mode is text. Unexpected host-shell termination does not have a Kanon-defined
exit meaning beyond these explicit branches.

## Evidence and reproduction

The routing inventory is defined by
`scripts/lib/artifact-files.js`, the wrapper files below `skills/`, the two
shared dispatchers, `src/v1/cli.js`, `src/v1/bin/kanon.js`,
`src/cli/args.js`, `src/cli/write.js`, `src/cli/todo.js`, and
`bin/kanon-write.js`. The generated runtime copies are checked against those
canonical sources by the existing skill and type-conformance tests.

The focused regression coverage is in `test/kanon.test.js`,
`test/v1-skills.test.js`, `test/v1-plugin.test.js`, and
`test/v1-types.test.js`. It fixes the wrapper inventories and dispatch targets,
accepted compatibility routes, rejected commands, runtime-error exit code,
launcher-error exit code, generated mirror equivalence, and exact artifact
allowlist.

To confirm that later work has not changed the baseline executable sources,
compare the named implementation paths with the immutable tag and run the
focused tests after inspecting their definitions:

```sh
git diff --exit-code v1.0.0 -- \
  bin src runtime skills scripts/lib/artifact-files.js

node --test \
  test/kanon.test.js \
  test/v1-skills.test.js \
  test/v1-plugin.test.js \
  test/v1-types.test.js
```
