# Kanon v1.1.0 release notes

Kanon v1.1.0 substantially reduces the active implementation while preserving
the supported package contract.

## What changed

- Removed duplicated legacy runtime and inactive generated evaluation output
  from the active package path.
- Kept the stable `orient`, `resume`, `verify`, `status`, `steer`, and
  `aswitch` skills.
- Preserved the v0.4 `brief`, narrowly scoped `ask`, `verify`, `resume`,
  `refresh`, and `todo` compatibility workflows.
- Retained a dependency-free ESM runtime, separate Codex and Claude manifests,
  Bash and PowerShell wrappers, advisory notice mode, and consent-gated writes.

## Validation and assurance

The standard stable lane validates the supported Node.js versions on Linux,
Windows, and macOS, builds and attests one exact tarball, and exercises that
same tarball as an installed package on all three operating systems.

This release does not claim evidence-strict support, independence, blinded
review, causal improvement, generalization, official holdout performance, or
independent validation. Historical evaluations remain development evidence and
accepted risks remain open.

## Compatibility and installation

Node.js majors 20, 22, 24, and 25 are supported. Install without lifecycle
scripts into a user-controlled plugin directory:

```text
npm install --ignore-scripts --prefix <plugin-directory> @mecglandorff/kanon@1.1.0
```

The package is a dual-host plugin distribution, not a JavaScript library or
global terminal CLI. Configure Codex CLI or Claude Code to load the complete
installed package root.

See `SECURITY.md` for private vulnerability reporting and `RELEASING.md` for
release, rollback, deprecation, and post-publication verification.
